# تحديث زميل 139 — التطبيق 2.0.5

ملفات التنزيل: Zameel_APP_139_APPEARANCE_SHORTS.zip، Zameel_ADMIN_139_RELEASE_CATALOG.zip، APPLY_UPDATE_139.ps1.
ضع الملفات الثلاثة في Downloads دون فك ضغط يدوي. حزمة ADMIN تسجل الإصدار الجديد فقط؛ واجهة لوحة التحكم ودالة admin-console لم تتغير، ولا تحتاج إعادة بناء اللوحة أو نشر الدالة.

## التعديلات

- فصل إعدادات الحساب (أعلى الرئيسية) عن إعدادات التطبيق (القائمة اليمنى): المظهر واللغة وتخصيص القائمة العائمة.
- ألوان نصوص وأيقونات وخلفيات وحقول وتعليقات تتكيف مع الأصلي والفاتح والداكن، مع حدود أوضح وأدوات فيديو مقروءة فوق الصور الفاتحة.
- التوثيق بجانب الاسم في القائمة اليمنى وطلبات المجموعات، ومساحة مستقلة للعلامة حتى عند اختصار الاسم الطويل.
- نقل ثقة أم غدر إلى القائمة اليمنى ← ألعاب زميل ← ثقة أم غدر. الكويز يبقى في موضعه الحالي.
- اختيار مدن الترويج عبر المحافظات الـ12؛ الاحتفاظ باختيارات من محافظات متعددة وإظهار المدينة ومحافظتها في ملخص الطلب. الاستهداف ما زال بالمدن المختارة؛ اختيار المحافظة لتصفية القائمة وحده لا يحدد مدنها كلها.
- إضافة شورتس تفتح شاشة النشر مباشرة؛ جلب قائمة المقاطع دون انتظار توقيع روابط الفيديوهات كلها، وفصل خطأ التحميل عن القائمة الفارغة مع إعادة المحاولة.
- معاينات الشورتس في القائمة والنافذة المنبثقة تستخدم الغلاف ومعاينة بديلة للمقاطع القديمة دون غلاف.
- فيديو المنشور المرئي يبدأ تلقائيًا بصوت مكتوم، ويتوقف خارج الشاشة أو عند الانتقال لشاشة أخرى. فتحه يعرض أدوات الصوت.
- التنقل بين الفيديوهات داخل العارض بالسحب للأعلى، والانتقال التالي عند اكتمال التشغيل إن وجد. الألبوم المختلط يحافظ على الصور والفيديوهات داخل المنشور نفسه.
- يتضمن إصلاح Kotlin الصريح لنوع TextureOverlay في مصدر العلامة المائية من 138.

التحليل البرمجي محليًا يمر بلا أخطاء، ونجحت فحوص ألوان وحالات المحافظات وتسجيل الإصدار. اختبارات Flutter المرئية، بناء Android، الأداء على الهاتف واتصال Supabase الفعلي لم تنفذ هنا؛ شغّلها كما يلي، ولا تعتبر فحص المصدر ضمانًا لسرعة الشبكة أو توافق كل هاتف.

## 1. التحضير والنسخة الاحتياطية — PowerShell

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass -Force
& "$env:USERPROFILE\Downloads\APPLY_UPDATE_139.ps1" -Stage Prepare
if (-not $?) { throw 'Preparation failed; stopped' }
```
يعرض تقدم النسخ الاحتياطي كل 15 ثانية، ثم يفك الحزمتين ويتحقق من بصمات الملفات. توقف عند أي خطأ وأرسل النتيجة قبل المتابعة.

## 2. النسخ والفحص — الأمران معًا في PowerShell

```powershell
$zameelUpdate139 = (Get-Content -LiteralPath "$env:USERPROFILE\Downloads\Zameel_Update_139_Path.txt" -Raw).Trim()
$zameelScript139 = Join-Path $env:USERPROFILE 'Downloads\APPLY_UPDATE_139.ps1'
& $zameelScript139 -Stage Copy -UpdateRoot $zameelUpdate139
if (-not $?) { throw 'Copy failed; stopped' }
& $zameelScript139 -Stage Check -UpdateRoot $zameelUpdate139
if (-not $?) { throw 'Checks failed; stopped' }
```
Check يشغّل flutter pub get ثم flutter analyze وكامل flutter test. لا يبني APK محليًا ولا ينزل NDK. لوحة التحكم لم يتغير كودها التنفيذي.

## 3. SQL واحد لتسجيل الإصدار

نفذ في PowerShell:

```powershell
& $zameelScript139 -Stage Sql1 -UpdateRoot $zameelUpdate139
if (-not $?) { throw 'SQL copy failed; stopped' }
```
الصق **محتوى الحافظة** في Supabase SQL Editor وشغله. لا تلصق أمر PowerShell في SQL Editor. يعتمد الملف على تحديث 138 المطبق سابقًا. لا يغير قرارات السماح/الإيقاف للإصدارات القديمة ولا يضع رابط تنزيل وهميًا.

بعد Success، نفذ في SQL Editor:

```sql
select version_name, build_number, is_allowed, download_url
from public.app_releases
where platform = 'android'
order by build_number desc
limit 3;
```
المتوقع أحدث ثلاثة: 2.0.5 (14)، 2.0.4 (13)، 2.0.3 (12). الرابط الجديد فارغ حتى تضيف رابط التنزيل الفعلي من لوحة التحكم بعد نجاح البناء.

## 4. رفع المستودعين — الأمران معًا في PowerShell

```powershell
& $zameelScript139 -Stage CommitAdmin -UpdateRoot $zameelUpdate139
if (-not $?) { throw 'Admin upload failed; stopped' }
& $zameelScript139 -Stage CommitApp -UpdateRoot $zameelUpdate139
if (-not $?) { throw 'App upload failed; stopped' }
```
يضيف السكربت ملفات 139 المحددة فقط. يحافظ على الملفات الأخرى المعدلة ويتوقف إذا وجد staged خارج التحديث. إذا واجه تعارضًا أو خطأ لا تستخدم git add . أو reset؛ أرسل المخرجات.
