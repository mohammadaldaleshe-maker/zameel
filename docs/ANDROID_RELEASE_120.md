# Android release preparation

The ZIP from GitHub Actions with signing=`test` uses an Android Debug certificate. It is for installation tests only. A new CI runner can have a different debug certificate, so subsequent test APKs may require uninstalling the previous test build. Never publish a test APK.

## Create and preserve the upload key

If you already own the upload key used for a published Zameel app, use that key. **Do not create a replacement.** Otherwise run `scripts/prepare-android-upload-key.ps1` on your Windows computer. It creates `D:\ZameelPrivate\zameel-upload.jks` and prompts for the password without putting the password into repository files. Back up the JKS and password in separate private locations before formatting Windows.

Configure these GitHub repository **Actions secrets**. Never commit their values:

- `ANDROID_KEYSTORE_BASE64`: Base64 representation of the JKS file (the script prints a clipboard command).
- `ANDROID_STORE_PASSWORD`: JKS password.
- `ANDROID_KEY_ALIAS`: `zameel-upload` if generated by the script.
- `ANDROID_KEY_PASSWORD`: key password (same as store password if Enter was pressed).
- `GOOGLE_SERVICES_JSON_BASE64`: Base64 content of the Firebase Android configuration, already used by test builds.

Run `Zameel Android APK` on `main` with signing=`signed`. The workflow runs analyze/tests, builds a universal APK and three ABI-specific APKs, builds a Play AAB, verifies signatures, and uploads separate APK/AAB artifacts. Prefer `app-arm64-v8a-release.apk` for a modern ARM64 phone; the universal `app-release.apk` works on all supported ABI variants. The AAB is for Google Play and requires the production upload key. If an installed test APK was signed with a different certificate, uninstalling it before installing signed builds may be required; back up any local-only data first.

## Store listing gates

- Publish and manually test `/delete-account.html` at a stable HTTPS URL outside the app; enter its working link in Play Console. The page authenticates against Supabase and invokes the same `delete_my_account` RPC as the app.
- Replace the draft privacy policy's contact placeholder with an address you control, verify all data practices, publish it at a stable HTTPS URL, and link it in the app and Play Console.
- Complete Data safety, advertising-ID, permissions, content rating and app access declarations using the actual production behavior. The APK requests contacts, location, camera, microphone, overlay, foreground-service and full-screen-intent permissions; retain each only where the product needs it.
- Check Supabase quota and test account deletion on a disposable user before publishing the deletion page.

The APK alone cannot prove loading speed. Compare first and second load times of the same image on a real device and a weak network. Existing ad uploads are compressed by the sales console, but legacy images need replacement there to benefit. Supabase on-the-fly image transformations require a paid tier and are not enabled by this patch.
